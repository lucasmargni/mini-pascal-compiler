# MEPA Interpreter

The **MEPA Interpreter** is the fifth stage of the Mini Pascal Compiler. Its main responsibility is to execute the **MEPA** code produced by the intermediate code generator, so that the behavior of the compiled programs can be verified.

## Overview

The interpreter simulates the MEPA machine (*Máquina de Ejecución para Pascal*): it loads a `.mep` file, resolves its labels and executes its instructions one by one until the `PARA` instruction is reached.

It is a standalone script written in Python and has no dependencies on the other stages of the compiler nor on external libraries.

## How It Works

The execution is performed in two steps:

1. **Loading**: the `.mep` file is read line by line. Each line may start with a label (`L1`, `L2`, ...) followed by an instruction and its arguments. Every instruction is checked to exist and to have the right number of arguments, and the position of each label is stored. Once the whole file is read, the labels used by `DSVS`, `DSVF` and `LLPR` are replaced by the address of the instruction they mark.
2. **Execution**: the machine starts at the first instruction and, in each step, executes the instruction pointed by the program counter `i`, updating the stack `M`, its top `s` and the display `D`, as defined in the MEPA specification. Every instruction increments `i` by one, except the jumps, calls and returns, which set it explicitly.

If an error is found during the loading, the program is not executed. If an error occurs during the execution (e.g. a division by zero), the execution stops and the instruction where it happened is reported.

## Supported Instructions

The following table lists the instructions emitted by the intermediate code generator. The interpreter also supports the rest of the MEPA instruction set (`MODU`, `LELN`, `IMLN`, `CONT`, and the instructions for arrays and records), even though they are not generated by this compiler.

| Instruction | Description |
|-------------|-------------|
| `INPP` | Start of the main program |
| `PARA` | End of the program |
| `RMEM n` / `LMEM n` | Reserve / free `n` memory cells |
| `APCT k` | Push the constant `k` |
| `APVL m,n` | Push the value of the variable at level `m`, offset `n` |
| `ALVL m,n` | Store the top of the stack in the variable at level `m`, offset `n` |
| `SUMA` `SUST` `MULT` `DIVI` | Addition, subtraction, multiplication and integer division |
| `DIVC` | Check that the divisor on the top of the stack is not zero |
| `UMEN` | Unary minus |
| `CONJ` `DISJ` `NEGA` | Logical `and`, `or` and `not` |
| `CMIG` `CMDG` `CMME` `CMNI` `CMMA` `CMYI` | Comparisons `=`, `<>`, `<`, `<=`, `>`, `>=` |
| `DSVS L` | Jump to label `L` |
| `DSVF L` | Jump to label `L` if the top of the stack is false |
| `NADA` | No operation, used to mark labels |
| `LEER` | Read an integer and push it |
| `IMPR` | Print the top of the stack and pop it |
| `ENPR k` | Enter a subprogram of level `k` |
| `LLPR L` | Call the subprogram at label `L` |
| `RTPR k,n` | Return from a subprogram of level `k` with `n` parameters |

## Running the Interpreter

To execute a MEPA program, run the following command from the root directory:

```bash
python3 mepa_interpreter/MepaInterpreter.py mepa_output/test_case1.mep
```

The values printed by `IMPR` are written to the standard output, one per line. The values for `LEER` are read from the standard input.

The following options are available:

| Option | Description |
|--------|-------------|
| `--input FILE` | Read the values for `LEER` from `FILE` instead of the standard input |
| `--trace` | Print each executed instruction along with the top of the stack (written to the standard error) |
| `--list` | Print the loaded program with the address of each instruction and exit, without executing it |

For example, to run a program that reads values from a file while tracing its execution:

```bash
python3 mepa_interpreter/MepaInterpreter.py mepa_output/test_case13.mep --input input.txt --trace
```

The `.mep` files can be generated with the [Intermediate Code Generator](../intermediate_code_generator/README.md#running-the-generator).
