# Syntactic Analyzer

The **Syntactic Analyzer** is the second stage of the Mini Pascal Compiler. Its main responsibility is to verify that the sequence of tokens generated by the lexical analyzer conforms to the grammar of the language.

## 📘 Overview

This component receives tokens produced by the lexical analyzer and checks whether they form a syntactically valid Mini Pascal program.

The analyzer validates, in a general way:

- Program structure and block organization
- Variable, procedure, and function declarations
- Compound and simple statements
- Expressions and operator precedence
- Control flow constructs such as `if` and `while`

Unlike the lexical analyzer, this stage does not process characters directly. Instead, it operates on the token stream and ensures that the source program follows the rules defined by the language grammar.

## ⚙️ How It Works

The syntactic analyzer is implemented as a **recursive descent parser**.

Each non-terminal symbol of the grammar is represented by a dedicated method, allowing the parser to recursively verify the structure of the input program.

As the token stream is processed:

- Expected terminals are matched against the current token
- Grammar productions are expanded through recursive calls
- Syntax errors are reported as soon as an invalid construct is detected

If the entire token sequence is successfully consumed and matches the grammar, the program is considered syntactically correct.

## ⚠️ Error Handling

When a syntax error is detected, the analyzer reports:

- The expected terminal
- The token that was actually found
- The row and column where the error occurred

This information helps identify the exact location and cause of invalid language constructs.

## ▶️ Running the Analyzer

To execute the syntactic analyzer, run the following command from the root directory:

```bash
python3 -m syntactic_analyzer.test_syntactic test_cases/test_case1.pas
```

Additional test cases are provided in the `test_cases` directory (e.g., `test_case2`, `syntactic_error_case1`).
You can also provide your own Pascal source file as input to validate different programs.

## 📖 Grammar

The syntactic analyzer implements the following grammar using a recursive descent approach.

<details>
<summary><strong>BNF Grammar</strong></summary>

### Programs and Blocks

```bnf
<program>
    ::= program id ; <block> .

<block>
    ::= <variable_declaration_part_opt>
        <subroutine_declaration_part_opt>
        <compound_statement>

<variable_declaration_part_opt>
    ::= <variable_declaration_part>
     | ε

<subroutine_declaration_part_opt>
    ::= <subroutine_declaration_part>
     | ε
```

### Declarations

```bnf
<variable_declaration_part>
    ::= var <variable_declaration> ;
        <variable_declaration_rep>

<variable_declaration_rep>
    ::= <variable_declaration> ;
        <variable_declaration_rep>
     | ε

<variable_declaration>
    ::= <identifiers_list> : <type>

<identifiers_list>
    ::= id <identifiers_list_rep>

<identifiers_list_rep>
    ::= , id <identifiers_list_rep>
     | ε

<type>
    ::= integer
     | boolean

<subroutine_declaration_part>
    ::= <procedure_declaration> ;
        <subroutine_declaration_part>
     | <function_declaration> ;
        <subroutine_declaration_part>
     | ε

<procedure_declaration>
    ::= procedure id
        <formal_parameters_opt> ;
        <block>

<function_declaration>
    ::= function id
        <formal_parameters_opt>
        : <type> ;
        <block>

<formal_parameters_opt>
    ::= <formal_parameters>
     | ε

<formal_parameters>
    ::= ( <formal_parameter_section>
        <formal_parameters_rep> )

<formal_parameters_rep>
    ::= ; <formal_parameter_section>
        <formal_parameters_rep>
     | ε

<formal_parameter_section>
    ::= <identifiers_list> : <type>
```

### Statements

```bnf
<compound_statement>
    ::= begin <statement>
        <compound_statement_rep>
        end

<compound_statement_rep>
    ::= ; <statement>
        <compound_statement_rep>
     | ε

<statement>
    ::= id <statement_id>
     | <compound_statement>
     | <conditional_statement>
     | <repetitive_statement>
     | <read_statement>
     | <write_statement>

<statement_id>
    ::= <assignment_without_id>
     | <procedure_call_without_id>

<assignment_without_id>
    ::= := <expression>

<procedure_call_without_id>
    ::= ( <expression_list> )
     | ε

<conditional_statement>
    ::= if ( <expression> )
        then <statement>
        <else_opt>

<else_opt>
    ::= else <statement>
     | ε

<repetitive_statement>
    ::= while ( <expression> )
        do <statement>

<read_statement>
    ::= read ( <variable> )

<write_statement>
    ::= write ( <expression> )
```

### Expressions

```bnf
<expression_list>
    ::= <expression>
        <expression_list_rep>

<expression_list_rep>
    ::= , <expression>
        <expression_list_rep>
     | ε

<expression>
    ::= <simple_expression>
        <expression_rep>

<expression_rep>
    ::= <relation>
        <simple_expression>
        <expression_rep>
     | ε

<relation>
    ::= =
     | <>
     | <
     | <=
     | >
     | >=

<simple_expression>
    ::= <unary_operator_opt>
        <term>
        <simple_expression_rep>

<simple_expression_rep>
    ::= <expression_operator>
        <term>
        <simple_expression_rep>
     | ε

<unary_operator_opt>
    ::= +
     | -
     | ε

<expression_operator>
    ::= +
     | -
     | or

<term>
    ::= <factor>
        <term_rep>

<term_rep>
    ::= <term_operator>
        <factor>
        <term_rep>
     | ε

<term_operator>
    ::= *
     | div
     | and

<factor>
    ::= id <function_call_without_id>
     | num
     | ( <expression> )
     | not <factor>
     | <language_constant>

<variable>
    ::= id

<function_call_without_id>
    ::= ( <expression_list> )
     | ε

<language_constant>
    ::= true
     | false
```

</details>
